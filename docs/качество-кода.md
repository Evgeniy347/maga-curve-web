# Качество кода

Правила для `site/js/**`. Проверять перед каждым коммитом кода.

## Одна реализация алгоритма

- **DRY жёстко.** Арифметика кривой живёт **только** в `curve.js` (`CubicCurve`).
  Страница, тест или форматтер, которому нужны λ, `x₃`, `y₃`, берёт их из
  `addTrace`, а не пересчитывает рядом.
- Арифметика поля — только `field.js`.
- **Модулей-обёрток не заводим**: тонкая функция поверх `curve.add` без собственной
  логики — второй адрес одного алгоритма.

## SOLID в применении к сайту

- **S** — модуль отвечает за одно: поле, кривая, геометрия секущей, привязка точки,
  график, контроллер страницы. Контроллер не содержит математики.
- **O** — новая форма кривой — новый объект-форма (`create`, `equation`), а не `if`
  внутри `AdditionPage`; новая панель — слушатель `onUpdate`.
- **L** — функция, принимающая кривую, работает с **любым** `CubicCurve`.
- **I** — функция берёт то, чем пользуется: кривую или `trace`, а не россыпь чисел.
- **D** — зависимость на переданный объект кривой, не на глобальные константы.

## Прочее

- Только ES-модули, `import` на уровне модуля; модули `site/js` грузятся и в Node
  (без обращения к DOM на верхнем уровне) — иначе их нельзя тестировать.
- «Магические» числа — именованная константа модуля (`STYLE`, `COLORS`).
- Никаких внешних JS-библиотек без необходимости; CDN только для шрифтов.
- Замеченное нарушение — техдолг: см. [техдолг.md](техдолг.md).
